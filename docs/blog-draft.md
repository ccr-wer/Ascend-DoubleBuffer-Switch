# 一个待验证的架构：把算子双缓冲迁移到上游热切换

> 草稿。文中所有涉及真实网络环境的部分均未验证（UNVERIFIED），唯一跑过的是本仓库的逻辑层演示与单元测试。

## 一、问题：链路不是断了才难受，变差的时候就已经难受了

校园网多拨/多上游的常见做法是 failover：探测发现当前线路不通，再把流量挪到备用线路。这个模型对"断线"有效，对"没断但质量变差"很迟钝——延迟拉高、丢包上升、吞吐掉下去的时候，连接还在，切换条件却还没满足。

更麻烦的是切换决策所依赖的信息：备用线路的质量往往是故障发生之后才开始测的。也就是说，最需要做判断的那一刻，手里的数据最少。

我的问题不是"怎么再多一条线路"，而是：**能不能在 A 还健康的时候，就把 B 的评估做完。**

## 二、设想：借双缓冲的语义，而不是借它的代码

算子开发里的双缓冲解决的是类似结构的问题：计算单元在消费 Buffer A，后台同时把 Buffer B 填满，然后只交换指针，计算与预取在时间上重叠。

映射过来是这样的：A 槽位是当前承载流量的上游；B 槽位是不承载流量、但持续被探测评估的候选；fill 是对 B 的预建与确认；swap 是把默认出口指到 B；release 是回收旧槽位，或者在 B 变差时回滚到 A。

这个映射真正改变的是时序，而不是拓扑。线路还是那两条，区别在于 B 的数据是在 A 还活着的时候攒下来的，切换决策用的是历史窗口而不是一次临时探测。当然，"预建"在真实校园网里是否被允许（认证、风控、同账号并发）是另一回事，这篇文章不回答它。

## 三、能验证的部分：把逻辑层单独切出来跑

为了把"时序设计"和"环境运气"分开，我把仓库切成三层：core 是纯逻辑，只做窗口统计和状态迁移，不做任何 I/O、不读时钟；数据源是接口，演示用剧本数据；动作层是桩，只打印 WOULD。

这样做的好处是，时序可以被确定性地重放。仓库里写了六个场景，每条都可断言：

1. 双槽都健康：没有任何迁移。
2. A 持续劣化、B 健康：A 窗口劣化占比达到阈值后，依次经过预建、确认、交换。
3. **A、B 同时劣化：判为疑似共享瓶颈，不切换。** 这是我最在意的一条。如果只盯 A 的质量，A 劣化就切 B，那么在"两条线路共享同一段上游"的情况下，切换只是换了条同样差的出口，还白白付出重连与认证成本。场景3把这种情形写进剧本：A、B 的劣化同步出现，状态机应停在不动作，而不是来回横跳。
4. A 只抖动一次：窗口占比不足，连"劣化"状态都不进入——单次毛刺不该触发切换。
5. 切到 B 之后 B 也变差：冷却结束后回滚到 A。
6. 切换之后的冷却期：A 继续劣化也不允许再次切换，SWAPPED 只出现一次。

六条场景都有对应的单元测试，`python demo.py` 可以把全过程打印出来。需要强调的是，这证明的是"给定输入时，状态机的时序符合设计"，不是"这套策略在真实网络上有效"。

写测试时还发现一个值得记录的问题：承载关系不能直接用状态表示。冷却期会把状态覆盖成 COOLDOWN，如果拿"当前状态是不是 SWAPPED"判断谁在承载，回滚分支就永远进不去，A 的旧劣化还会把结果挤成"双槽同时劣化"。所以骨架里把承载槽位拆成独立标志，冷却只负责禁止动作。

## 四、明确未验证的部分

以下都是 UNVERIFIED，详细清单在 docs/unverified.md：

- A、B 劣化同步是否真的能推断共享段瓶颈，还是仅仅巧合；
- 预建 B、切换出口是否触发校园网重认证或风控；
- 各平台改路由 metric、调代理分流、提权的具体做法与副作用；
- 阈值与窗口参数：仓库里的 80ms、5%、1Mbps、window=10、ratio=0.6、cooldown=5 全是占位默认值，正确做法是按实测分布取 P95/P99 再标定；
- 切换对存量连接的影响，以及预建本身的成本。

我不会给这组场景配上任何"切换更快""中断更短"的数字，因为没有测过。

## 五、开放接口：留给你填的两块

**ProbeSource**：接口只有一个方法，`probe(node_id) -> ProbeResult`，返回延迟、丢包、吞吐和时间戳。接真探测时，把 ICMP/HTTP/代理延迟的采集写在这个接口后面即可，状态机不需要改动；建议先用它做只读采集，攒基线数据，再谈切换。

**adapter**：动作层要兑现三件事——预建不破坏现有 A、切换幂等且留快照、回滚按快照恢复。平台差异（路由表与策略路由、网络管理器覆盖、提权方式）都在 adapter/README.md 里列了清单，默认应当 dry-run。

如果你正好有可测试的环境，最有价值的贡献不是再写一套状态机，而是把 unverified.md 里的某一条变成"已验证"，并附上原始数据。
